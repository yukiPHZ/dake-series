- 起動直後はUI表示を最優先する。fitz / Pillow / pypdfなど、UI表示に不要なPDFバックエンドはロード・レンダー・保存・CLI実行時に遅延読み込みする。
- TkinterDnDは安定性を優先し、既存のドロップ入力を維持する。
- packaged版の起動速度を実測する。現行相当onefileとonedirを各10回以上測り、個別値・中央値・p90・最速・最遅を記録する。
- SelectはPyInstaller onedirを正式候補として検証し、起動・PDF入力・DnD・表示・保存・リフレッシュが正常なら採用する。共通buildルールのonefile推奨に対する本アプリの例外とする。
- スプラッシュやアニメーションで待ち時間をごまかさない。依存更新は目的とせず、確認した実バージョンを検証後に固定する。

## リフレッシュ正式定義

現在の作業セッションを完全に破棄し、次のPDFをすぐ追加できる初期状態へ戻す操作とする。

- 破棄: 現在PDF、ファイル名、ページ数、サムネイルとキャッシュ、選択ページ、Shiftアンカー、範囲入力とエラー、完了状態、エラー状態、旧世代の未実行レンダー要求、追加enqueue用after、旧PDFの開いたハンドル。
- generation更新とcancel Eventで旧要求・旧結果を無効化する。実行中の1ページは完了してよいが、それ以降の旧処理は継続しない。
- documentは所有するworkerでcloseする。close制御要求を新PDFより先に処理する。終了時・worker例外時もcloseする。
- 手動指定の保存先だけ保持する。自動保存先は破棄する。出力済みファイルは削除しない。
- UIはファイル名「未選択」、ページ数初期表示、選択0、範囲空、サムネイル空、ステータス「未選択」、PDF追加案内へ戻す。
- 保存中のキャンセルは今回の対象外とし、既存の保存保護を維持する。

## サムネイル生成方針

- 全ページ先行生成は禁止。現在見えているページを高優先度で、前後の近接ページ・最小限の先読みを低優先度で生成する。
- スクロール時は現在必要なページを追加要求し、不要な待機要求を破棄する。大量PDFでも全ページ生成を待たない。
- サムネイル寸法から倍率を求め、縦横比を維持して必要寸法へ直接レンダーする。
- PDF処理は固定worker、UI反映はqueue / afterでmain threadへ戻す。

## 準備完了の意味

PDF基本情報取得済み、現在画面に必要なサムネイル表示済み、UI操作可能の3条件で準備完了とする。
全ページサムネイル生成完了は条件にしない。近接ページ先読みは準備完了後も行ってよい。

## キャッシュ方針

- 全ページの画像を永続保持しない。LRU上限の初期値を96ページとし、実測で調整できる。
- キャッシュヒットは最近使用扱いにする。evict後は必要になれば再生成可能とする。
- キャッシュ破棄は選択状態・ページ番号・範囲指定に影響しない。

## 互換性と検証

- 既存のmerged / single保存、Shift選択、範囲入力、完了ダイアログ、保存フォルダopenを維持する。元PDFは変更しない。
- --from-shimarisu の inputs / pages / output / silent、および既存exit code (成功0・失敗1) を維持する。
- 3 / 30 / 100 / 300ページ、途中refresh・即別PDF・元PDF rename/move、LRU再生成、保存後SHA-256不変を検証する。
- packaged版とDPI確認状況、未確認項目、PyMuPDFライセンスと配布条件の追加確認要否を docs/PERFORMANCE_REFRESH_REPORT.md に記録する。未確認をPASSにしない。
