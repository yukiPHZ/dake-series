## 試験方法と確認範囲

保存・境界試験は Node.js テストで実施。ネイティブAPI境界はモックで許可パス、送信元、原画像保護、復旧、画面遷移・権限・終了待ちを確認しました。

編集エンジンは実 Electron renderer と Canvas を使用。ブラシ・消しゴム・ペン・ノードの一部は Electron のネイティブマウス入力から実行し、画素値やパスデータを検査しました。統合試験は実 UI・preload・IPC・実ファイルを通していますが、ネイティブダイアログの返答は試験パスへ差し替えています。実 OS 保存ダイアログの操作は、別途 Computer Use により手動確認しました。

再起動試験は自動保存後に `app.exit()` で通常の終了処理を通さず終了し、異なる PID の次プロセスで復旧 UI を表示・操作しました。物理的な電源断、ディスク置換中の終了を再現したものではありません。

QA復旧先は `STADIO_USER_DATA` で分離。素材はコードで生成した抽象画像・図形・日本語テキストで、ユーザーの私的コンテンツや秘密情報は使用していません。すべて同じWindows PCでの試験です。別PC・別GPU・別Windows環境への一般化はしません。

## 検証済みの動作

- 図形追加、複製の独立ID、削除、ロック、グループ・解除、変形、取り消し・やり直し。グループ化前後の描画ピクセル保持。
- ブラシによる実画像ピクセル変更、消しゴムによるアルファ変更、取り消しによる復元。1回の筆操作が1履歴。
- ペンドラッグの三次ベジェ、ノード編集、閉じたパス先頭点変更時の他アンカー固定。
- 画像調整の保存・復元、調整リセット時の元画素保持、作品の切り抜き・取り消し。
- 実PNG読込み、画像・文字・パス混在サンプル、UIでの調整・数値変形・複製・履歴。
- `.dake`保存と再読込み。複雑な作品の保存前後のPNGがバイト単位で一致。
- 入力PNG・SVGのSHA256が全操作前後で一致。元ファイルへの上書きとハードリンク経由の上書きを拒否。
- 2回目保存で前回ファイルを `.bak` に保持。バックアップ失敗で既存ファイルを保護し一時ファイルを除去。
- 切断JSON、過大入力、不正寸法、未知版、過深構造、外部URL、実行要素付きSVGを拒否。内部参照SVGは受理。
- 壊れた作品・画像デコード失敗でも現在の作品を保持。
- PNG/JPEG/WebP/SVGの実ファイル生成、寸法、形式、JPEG不透明背景、SVGの文字・パス・埋め込み画像を確認。SVG再読込み後も編集可能。
- PNGが表示ズームに依存しないことを確認。
- 自動復旧のディスク保存・読戻し・明示破棄、破損最新候補から前世代への復旧。
- 別プロセスで復旧UIから未保存名・レイヤーを戻し、ベクターを再編集して保存。前回保存バックアップと古い復旧候補の削除。
- 閉じる操作のキャンセルで現在作品を保持。表示移動だけでは未保存にならない。

## 修正した不具合

表示操作で未保存になる問題、Fabric 7の中央原点によるサンプル文字・パス配置ずれ、壊れた画像を黙って飛ばす読込み、ブラシ開始時に選択画像が失われる問題、閉じたパスの先頭ノード編集で別点がずれる問題、通常保存後に旧復旧候補が残る問題を修正しました。保存世代の照合により、保存中に行われた新しい編集を誤って破棄しません。

## 応答性

現在PCの最終統合試験: 操作準備414ms、1200×800作品のPNG出力171ms、JPEG167ms、WebP168ms、SVG214ms。ZIPから展開した配布EXEの操作準備は947msでした。全PCの保証値ではありません。

初回エンジン負荷試験は2048×1536、描画6回15〜20ms/回、取り消し3ms、出力51msでした。非表示ウインドウのrequestAnimationFrame間隔1007msは描画抑制による測定の影響で、UI停止の証拠ではありません。

調整・復元・調整付き筆操作終端の画像処理をworkerへ移しました。最終52項目試験では以下を観測しています。イベントループの間隔はタイマーで測定し、上記の非表示requestAnimationFrameとは区別します。

| 操作 | 12MP（4000×3000）総時間 / 最大イベントループ間隔 | 32MP（8000×4000）総時間 / 最大イベントループ間隔 |
| --- | --- | --- |
| worker画像調整 | 294 ms / 31 ms | 733 ms / 97 ms |
| 調整付き画像の再読込み | 297 ms / 63 ms | 622 ms / 97 ms |
| 調整付き画像の筆操作完了 | 336 ms / 74 ms | 734 ms / 143 ms |

同条件のCPU参照による画像調整は12MP448 ms、32MP993 msでした。worker結果とCPU参照の画素一致、処理中の競合防止、原画素保持、筆操作1回分の取り消しを確認しました。32MP画像を11回描画した試験では、履歴が13状態・概算90.1 MiBへ整理され、取り消しで画素が戻りました。

画像処理中にもイベントループへ戻ることを確認した範囲です。143 msの間隔も観測しており、常時0.1秒以内という保証はしません。上限作品の全組合せ・大量ベクター・長時間制作は未検証です。

## 配布・ライセンス

Fabric7.4.0・Electron44.4.5・esbuild0.25.12の公式固定タグでMIT条件を確認。一次資料URLはORIGINAL.md。配布のTHIRD_PARTY_NOTICES.txt、Electron runtimeのLICENSEとLICENSES.chromium.html、編集可能な作例が含まれることを確認しました。

ZIPにパストラバーサルがなく、展開した78ファイルの名前・SHA256が配布元とすべて一致しました。展開したEXEからapp.asarを読み、日本語UI・ネイティブ境界が初期化し、混在サンプル、ローカル画像worker、復旧データの保存、1200×800 PNG書き出し、正常終了まで9項目に合格しました。起動947ms、想定外エラー0件。これは同じWindows PCで開発作業ディレクトリに依存せず動くことの確認です。

文書だけの更新後もruntimeを変えずZIPを再作成し、アーカイブ照合を再実行します。最終ZIPのサイズ・ハッシュは更新されるため本文に固定せず、`evidence/archive-results.json`を参照します。検証したruntimeのEXE・app.asar SHA256は`evidence/packaged-results.json`に記録しています。
