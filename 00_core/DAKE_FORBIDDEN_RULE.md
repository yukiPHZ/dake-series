# DAKE_FORBIDDEN_RULE

DAKEシリーズで避けることをまとめた禁止事項です。

## 多機能化禁止

- 1つのアプリに複数の目的を入れない。
- 便利そうという理由だけで機能追加しない。
- 切替タブやモードで何でもできるアプリにしない。
- 目的が増えたら別アプリ化を検討する。

## 過剰UI禁止

- 大きすぎる装飾を置かない。
- グラデーションや派手な演出を増やさない。
- アイコンや説明文を増やして操作を重くしない。
- 主操作より目立つ背景や装飾を置かない。

## 完璧主義で止まることの禁止

- 100点の汎用ツールを目指さない。
- まず現場の1作業が終わる状態を優先する。
- 不要な設定や例外対応で完成を止めない。
- ただし、文字化け、起動不能、データ破壊リスクは止めて直す。

## 過去プロジェクト流用の注意

- 過去コードを丸ごと流用しない。
- 不要な設定、画面、依存関係を持ち込まない。
- DAKEの単機能思想に合う部分だけを使う。
- UI文言、フッター、アイコン、READMEはDAKE仕様へ揃える。

## 文字化け放置禁止

- READMEの `????` を放置しない。
- UIの mojibake を放置しない。
- `release_body.md` の文字化けを放置しない。
- スクリーンショットで文字化けが見えたら修正する。

## Release運用の禁止

- `DAKE_COMMON_SPEC.md` のWindows単独exe要件を満たさず出荷しない。高速化を理由にonedir・隣接runtime必須へ変更しない。
- 技術的に満たせない場合は出荷保留とし、原因・代案を報告する。既存の出荷ツールが対応していても旧例外を新規出荷へ継承しない。
- 旧クレジットや年号を新共通フッターへ戻さない。正式文字列は共通仕様を参照する。
- 規則更新だけで既存exeを検証済みとしない。過去の出荷・計測履歴を新方針に合わせて改ざんしない。

- ORIGINAL以外に個別仕様の別正本を増やさない。READMEは派生ビュー、00_coreはシリーズ共通規則として分担する。
- `release_url` を推測で入れない。
- GitHub Releaseを無断で編集しない。
- `release_body.md` とREADMEを別内容にしない。
- exe名が違うものをReleaseに添付しない。

## Git管理の禁止

- `build/` をcommitしない。
- `dist/` をcommitしない。
- `*.spec` を不要にcommitしない。
- `*.exe` をGitに入れない。
- 個人設定やローカルパスを入れない。

## 画面設計の禁止

- 起動直後に何をすればよいか分からない画面にしない。
- 重要なボタンをスクロールしないと押せない位置に置かない。
- フッターで主操作を押し下げすぎない。
- エラーを専門用語だけで表示しない。
- 空状態を壊れた画面に見せない。
