# SHIMARISU_DAKE_FLOW

しまりすくんとDAKEアプリを組み合わせるときの責務分担と呼び出し構造です。
しまりすくんは判断し、DAKEは処理します。

## 役割

| 担当 | 役割 |
| --- | --- |
| しまりすくん | 目的理解、対象ファイル判断、実行アプリ選定、引数組み立て、結果解釈 |
| DAKE | 単機能処理、ファイル変換、保存、exit code返却 |

DAKE側に、判断・会話・複雑な分岐を増やしません。

## 基本思想

- しまりす = 判断。
- DAKE = 処理。
- GUI = 人が迷わず使う入口。
- CLI = しまりすくんが迷わず呼ぶ入口。
- 処理本体は同じでも、入口とエラー表示は分ける。

## 呼び出し構造

```text
利用者
  ↓ 依頼
しまりすくん
  ↓ アプリ選定・引数作成
DAKE exe --from-shimarisu --input ... --output ...
  ↓ stdout / stderr / exit code
しまりすくん
  ↓ 結果説明・次の判断
利用者
```

## CLI契約

しまりすくんがDAKEを呼ぶときは、以下を契約として扱います。

- CLI実行には必ず `--from-shimarisu` を付ける。
- DAKEはGUIを出さない。
- DAKEは勝手に上書きしない。
- DAKEは成功時stdoutへJSONを返す。
- DAKEは失敗時stderrへ短いエラーを返す。
- DAKEはexit codeで結果を返す。
- DAKEはTracebackを出さない。

## 入力責務

しまりすくん側:

- どのDAKEアプリを使うか判断する。
- 入力ファイルの候補を選ぶ。
- 必須引数が揃っているか事前確認する。
- 出力先が既存ファイルと衝突しないように決める。
- 複数候補がある場合は利用者へ確認する。

DAKE側:

- 受け取った入力が存在するか確認する。
- 対応形式か確認する。
- 処理に必要な最小検証を行う。
- 不正な入力はexit codeで返す。

## 出力責務

しまりすくん側:

- 保存先名を決める。
- 既存ファイルがある場合は別名を考える。
- 成功後、利用者へ出力先を伝える。
- 次の処理が必要なら、次のDAKEを選ぶ。

DAKE側:

- 指定された保存先へ出力する。
- 既存ファイルがある場合は止める。
- 成功時はstdout JSONへ出力パスを返す。
- 一時ファイルは残さない。

## 失敗時ルール

DAKEが失敗した場合:

- exit codeは `DAKE_CLI_SPEC.md` に従う。
- stderrは1行目で原因が分かるようにする。
- Tracebackは出さない。
- GUIダイアログは出さない。
- 入力ファイルや既存出力を壊さない。

しまりすくんが失敗を受け取った場合:

- exit codeとstderrを読んで原因を分類する。
- すぐ再実行できる場合は、別名保存などを提案する。
- 入力不足や判断不足の場合は、利用者へ短く確認する。
- DAKE側の内部例外を長く説明しない。

## 実務パイプライン想定

### PDF処理

```text
PDF選定 → DAKE_PDF_Merge CLI → DAKE_PDF_Compress CLI → 出力先案内
```

- しまりすくんは順序と保存名を決める。
- DAKEは結合、圧縮などの処理だけを行う。

### 画像処理

```text
画像選定 → DAKE_Image_Resize CLI → DAKE_Image_ToPDF CLI → 出力先案内
```

- しまりすくんは画像群と最終形式を判断する。
- DAKEは変換と保存だけを行う。

### 書類作成

```text
入力情報整理 → DAKE_Document_Cover CLI → PDF保存 → 出力先案内
```

- しまりすくんは入力情報の不足を確認する。
- DAKEは指定された内容でPDFを作る。

## UIを止めないためのルール

- CLI処理中にGUIを起動しない。
- GUIボタンから重い処理を呼ぶ場合は、既存のDAKE UIルールに従ってUIを固めない。
- しまりすくんから呼ぶ処理は、子プロセスとして完結させる。
- 長時間処理はタイムアウトと再実行判断をしまりすくん側で持つ。

## 新規アプリ作成時の流れ

1. まずGUI単機能アプリとして完成させる。
2. 処理本体を関数化する。
3. `DAKE_CLI_TEMPLATE.md` を使って `--from-shimarisu` 分岐を足す。
4. READMEにCLI例を短く書く。
5. GUI通常起動とCLI起動を両方確認する。
6. Release前レビューで `DAKE_CLI_SPEC.md` に照らして確認する。

## 迷ったとき

- 判断はしまりすくんへ戻す。
- 処理はDAKEに閉じる。
- 上書きしない。
- 止めない。
- 長く説明しない。
