# DAKE Pack Manual Delivery Rule

## 目的

DAKE Pack商品をStripeで販売する場合の、決済後の手動配布運用を定義する。

このルールは、Payment Linkを作成する前に「購入者が決済後に商品を受け取れる」状態を保証するためのものです。

## 対象商品

- DAKE_Pack_Document
- DAKE_Pack_Memo

## 採用する配布方式

- delivery_method: `manual_email_private_download`
- Stripe決済完了後、購入時に入力されたメールアドレス宛に、手動でダウンロード案内を送る。
- 自動ダウンロードではない。
- 案内は購入者ごとに確認して送信する。
- 公開URL、誰でも取得できるURL、GitHub public repo上のPack ZIPは使用しない。

## 決済確認

配布前にStripe Dashboardで最低限以下を確認する。

- 支払いが成功している。
- 支払いが本番環境である。
- 購入商品が対象Packである。
- 支払い金額が正しい。
- 通貨がJPYである。
- 購入者メールアドレスが確認できる。
- 返金済み、キャンセル済みではない。

決済未完了の場合は配布しない。

## 配布ファイル確認

配布前に以下を確認する。

- 対象Pack名
- ファイル名
- ファイルサイズ
- SHA256
- 購入商品との一致

Stripe登録後にPack ZIPを更新した場合は、正本、配布記録、SHA256を再確認する。古いZIPを誤送信しない。

## 購入者への案内

購入者には以下を案内する。

- 本商品はデジタル商品のPackである。
- Stripe決済完了後、購入時に入力されたメールアドレス宛に、次営業日以内にダウンロード方法を案内する。
- 自動ダウンロードではない。
- 案内メールが届かない場合は、迷惑メールフォルダを確認し、購入時メールアドレスと商品名を添えて問い合わせる。

## 配布期限

標準の配布期限は、決済確認後、次営業日以内とする。

「即時ダウンロード」と誤解させる表現は使用しない。

## 配布記録

実際の購入者情報はGitで管理しない。

repo内にはサンプル形式のみを置く。実運用ログは、安全なrepo外ローカル領域または適切な管理場所に保存する。

## 再送

購入者から再送依頼があった場合は、以下を照合する。

- 購入時のメールアドレス
- Stripeの支払い情報
- 購入したPack
- 支払い成功状態
- 過去の配布記録

本人確認と購入記録を確認できた場合のみ再送する。

## メール不達

メール送信に失敗した場合は、`delivery_failed` として記録し、メールアドレスの入力誤り、Stripe上の購入情報、可能な連絡手段を確認する。

解決できない場合は、既存のDAKE Store利用規約、返金方針、個別対応方針に従う。

## 返金・配布不要時

返金済み、キャンセル済み、重複購入など、配布しない判断をした場合は、配布せず、必要な範囲だけ運用ログに記録する。

## 個人情報・Secret管理

以下をGit、generated JSON、Store静的ファイル、Markdownレポート、publicフォルダへ保存しない。

- 購入者メールアドレス
- 氏名
- Stripe Payment ID
- Payment Link IDと購入者を結び付ける実運用ログ
- 非公開ダウンロードURL
- Stripe Secret Key
- Webhook Secret
- カード番号、セキュリティコード、認証情報

## 禁止事項

- Stripe APIをこのルール文書から実行しない。
- Secretをファイルへ保存しない。
- 公開ダウンロードURLを正本、generated JSON、Store静的ファイルへ記録しない。
- GitHub public repoへPack ZIPを置かない。
- 実際の購入者情報をGit管理しない。
- メール添付を標準方式にしない。
- 自動ダウンロードと誤解される案内をしない。

## 将来の自動配布移行

将来、非公開ストレージ、期限付きURL、Webhook、購入者DBなどを使う自動配布へ移行する場合も、正本は `ORIGINAL.md` とし、Payment Link URLや配布方式の確定結果は正本へ戻す。
