# DAKE_UI_GUIDE

DAKEアプリの見た目と操作感の基準です。

## UI品質の基本

- 起動直後に「何をするアプリか」が分かる。
- 主操作は1つか2つに絞る。
- ユーザーが読む量を減らし、操作の道筋を画面構造で示す。
- 密度は高すぎず、余白は広すぎない。
- 装飾より、仕事が止まらないことを優先する。

## フォント

推奨順:

1. `BIZ UDPGothic`
2. `Yu Gothic UI`
3. `Meiryo`
4. `TkDefaultFont` など環境標準

ルール:

- Windowsで読みやすい日本語フォントを優先する。
- タイトルは太字、説明文は補助色で控えめにする。
- 長い説明を画面内に置かない。詳しい説明はREADMEへ寄せる。

## 色

基本:

- 背景: 薄いグレーまたは白系。
- カード・入力面: 白。
- 本文: 濃いグレー。
- 補助文: 中間グレー。
- アクセント: 青系を基本に、主ボタンと状態表示で使う。
- エラー: 赤系。
- 成功: 緑系。

避けること:

- 過度なグラデーション。
- 装飾のためだけの色数増加。
- 主機能より目立つ背景や装飾。

## 余白とレイアウト

- 外側余白は20〜24px程度を基準にする。
- 関連する入力欄は同じまとまりに置く。
- ボタン群は主ボタンと補助ボタンの位置を分ける。
- 画面サイズを小さくしてもフッターやボタンが重ならないようにする。
- 横幅が狭い場合は、左右配置を上下配置へ切り替える。

## ヘッダー

- 機能タイトルを1つだけ置く。
- 説明文は1行程度にする。
- アプリ名を画面内で何度も繰り返さない。
- H1相当の文字は、主画面の最上部だけに使う。

## ボタン

- 主ボタンは1画面に1つを基本にする。
- 主ボタンには動詞を使う。
- 補助ボタンは白または控えめな色にする。
- 危険操作は即実行せず、必要なら確認する。
- 処理中は二重実行を防ぐためボタンを無効化する。

## 入力欄

- 入力の目的が分かるラベルを付ける。
- 初期値がある場合は、現場でそのまま使える値にする。
- 形式がある入力はヒントを表示する。
- 入力エラーは対象と理由を短く伝える。

## スクロール

- 画面が縦に長いアプリはスクロール領域を用意する。
- 主操作ボタンはできるだけ見失わない位置に置く。
- スクロールしないと最初の操作ができない設計は避ける。

## 初期表示

- 起動直後の状態でスクリーンショットに使える見た目にする。
- 空状態も完成した状態として整える。
- 「ここにドロップ」「PDFを追加」など、最初の行動が分かる表示にする。
- 未取得、未選択、未入力の状態をエラーに見せない。

## フッター

- DAKE共通コピーとリンクを控えめに表示する。
- 主操作の邪魔にならない位置に置く。
- 狭い画面では折り返しや中央寄せにする。
- フッターのために画面が使いにくくなるなら、サイズと情報量を減らす。

## DAKE UI品質判断基準

レビュー時の問い:

- 起動して3秒以内に用途が分かるか。
- 主操作が迷わず見つかるか。
- 読まないと使えない説明が画面に増えていないか。
- 画面を狭くしても文字やボタンが崩れないか。
- 何も選んでいない状態が不安に見えないか。
- 処理中・完了・失敗が分かるか。
