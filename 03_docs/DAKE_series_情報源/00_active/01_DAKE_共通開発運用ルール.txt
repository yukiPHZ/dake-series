【DAKE共通開発運用ルール｜2026-06-12 現行】

## 基本方針

DAKEシリーズでは、実装・修正・出荷の前に、対象の正本と派生ビューを確認する。

確認順：

```text
1. ORIGINAL.md
2. README.md
3. DAKE_META
4. release_body.md
5. booth_product.txt
6. 関連仕様ファイル
```

矛盾がある場合は ORIGINAL.md を優先する。

## ファイルの位置づけ

ORIGINAL.md：
- 真の正本
- アプリ、Pack、商品、販売表示の最後に信じる場所

README.md：
- GitHub公開ビュー
- 公開説明用の派生ビュー

DAKE_META：
- Launcher、dakeapp.com、管理ツール向けの機械利用ビュー

release_body.md：
- GitHub Release用ビュー

booth_product.txt：
- BOOTH登録用ビュー

Store表示：
- 販売ビュー

## Codex作業ルール

Codexは作業前に ORIGINAL.md を最初に確認する。

ORIGINAL.md がない既存対象では、移行完了まで README.md を暫定参照してよい。
ただし、今後も扱う対象であれば ORIGINAL.md 作成を提案する。

## 実装方針

- 既存完成版がある場合はゼロから作らず活かす
- ロジックを壊す変更は後回し
- 差分が小さい修正から行う
- UI文言は UI_TEXT 管理
- 日本語UI文言を text="" に直接書かない
- build、dist、*.spec、*_config.json、__pycache__、*.pyc はGit管理しない

## Store同期

Storeへ反映する場合は、DAKE_series側で次を実行する。

```powershell
python tools\store\sync_store_to_site.py
```

確認項目：
- items件数
- type別件数
- payment_status件数
- source_policy
- do_not_edit: true
- shimarisu_pack

## 完了報告

Storeや正式出荷が関係する場合、完了報告には次を含める。

- ORIGINAL.md確認有無
- README / release_body / booth_product 整合確認
- GitHub Release URL
- BOOTH URL
- dakeapp.com掲載URL
- store.dakeapp.com商品詳細URL
- payment_status
- Stripe導線有無
- BOOTH導線有無
- Store同期結果
- Cloudflare反映確認
- final git status
